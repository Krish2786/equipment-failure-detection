# MachineGuard • Early Detection of Equipment Failure
> **College Engineering Capstone Project:** Machine Learning System for Early Detection of Equipment Failure in Industrial Telemetry.

MachineGuard is an industrial-grade predictive maintenance frontend dashboard designed for CNC machining centers, high-speed lathe spindles, and heavy hydraulic presses. Built with React 18, Vite, and custom CSS3 variables, it implements a continuous failure probability estimation paradigm (`0.0% – 100.0%`) based on physical sensor telemetry.

---

## 1. Core Architecture & Technologies
- **UI Framework:** React 18+ (Vite bundler, JavaScript ES6+ `.jsx`)
- **Routing:** React Router v6 (`react-router-dom`)
- **Data Visualizations:** Recharts (time-series areas, donut charts, scatter distribution envelopes, ROC/PR curves, feature importance bar charts)
- **Icons:** `lucide-react`
- **State Management:** React Context API (`PredictionContext`) with custom hook `usePrediction()` and synchronized `sessionStorage` persistence across route changes
- **Styling:** Modular Vanilla CSS3 with dual-theme design tokens (Dark Theme default, toggleable Light Theme) inspired by Grafana and Siemens MindSphere
- **Zero External UI Libraries:** Pure vanilla CSS layout grids, flexboxes, and custom glassmorphism. No Tailwind CSS, Next.js, or heavyweight component frameworks.

---

## 2. Continuous Failure Probability Paradigm
Rather than constraining diagnostics to a coarse binary classification ("Failure" vs "No Failure"), MachineGuard calculates the exact continuous **Failure Probability Percentage** ($0.0\%$ to $100.0\%$) using the Random Forest probability estimator (`predict_proba`).

The continuous percentage is categorized into 4 operational risk tiers:
1. **0.0% – 24.9% • Optimal Operation:** Routine telemetry logging active. No physical intervention required.
2. **25.0% – 49.9% • Elevated Wear:** Schedule inspection in the next scheduled maintenance window.
3. **50.0% – 74.9% • High Failure Risk:** Prioritize preventive maintenance. Prepare replacement cutting inserts and inspect thermal loops.
4. **75.0% – 100.0% • Critical Imminent Risk:** Immediate intervention recommended. Halt cutting cycle immediately to avoid catastrophic spindle seizure.

## 3. Physical Sensor Inputs & Failure Mechanics
The system evaluates 5 key physical telemetry variables:
- **Air Temperature [K] (290.0 – 310.0 K):** Ambient ambient temperature surrounding the machine enclosure.
- **Process Temperature [K] (300.0 – 320.0 K):** Cutting-zone temperature generated by tool-workpiece friction. Difference $\Delta T = T_{\text{proc}} - T_{\text{air}}$ determines heat dissipation capability ($\Delta T < 8.6\text{ K}$ causes heat dissipation failure).
- **Rotational Speed [rpm] (1,000 – 3,000 rpm):** Spindle velocity. Extremely high speeds create centrifugal bearing loads; low speeds with high torque cause stator overload.
- **Torque [Nm] (3.0 – 80.0 Nm):** Mechanical torque exerted by the spindle. High torque indicates dull cutting edges or hard material inclusions.
- **Tool Wear [min] (0 – 260 min):** Cumulative cutting engagement time. Interacts multiplicatively with torque: $\text{Torque} \times \text{ToolWear} > 11,000$ triggers overstrain failure.

## 5. Getting Started

### Prerequisites
- Node.js (v18.0 or higher)
- npm (v9.0 or higher)

### Installation
From the root workspace or `equipment-failure-frontend`:
```bash
cd equipment-failure-frontend
npm install
```

### Running Locally
To launch the Vite development server:
```bash
npm run dev
```
Open [http://localhost:5173](http://localhost:5173) in your web browser.

### Building for Production
```bash
npm run build
```
The production bundle will be generated in `equipment-failure-frontend/dist/`.

## 6. Future Backend Integration (FastAPI / Scikit-learn)
To connect this interface to a live Scikit-learn Random Forest model served via Python FastAPI or Flask:
1. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
2. Update `VITE_USE_MOCK_PREDICTOR="false"` and set `VITE_API_URL="http://localhost:8000/api"`.
3. In `src/services/predictionService.js`, the payload matches the standard dictionary:
   ```json
   {
     "air_temperature": 298.4,
     "process_temperature": 308.7,
     "rotational_speed": 1500,
     "torque": 40.2,
     "tool_wear": 120
   }
   ```
4. The backend should return the JSON structure matching the contract in Section 7 of the technical specification.
